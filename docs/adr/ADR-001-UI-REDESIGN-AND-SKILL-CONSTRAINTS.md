# ADR-001: 仓配协同工作台 v2.0 UI 现代化重塑与多业务链深度整合

## 状态 (Status)
**Accepted** (已采纳并通过测试验证)

## 背景 (Context)
仓配订单汇总工具（v1.x）包含四大独立模块：补货汇总、更新良品库存、送货单与采购需求、猫超开票通知单，以及 5 个分散的预设配置项。
存在以下架构与交互摩擦：
1. **业务流割裂**：用户完成「补货汇总」生成表三后，若需校准实际库存，必须手动另存为文件，再切换到「更新良品库存」页面重新寻找并上传，流程割裂严重。
2. **配置入口分散**：商品预设、仓库工厂、仓库别名映射、开票信息散落在各个业务页面的局部按钮，用户维护主数据极为繁琐。
3. **UI 体验局促**：顶部横排 Tab 与随 Tab 剧烈跳动的动作按钮引发视觉不稳定；部分组件缺乏严谨的 8 态支持与 Tailwind 规范。

## 决策 (Decision)
基于用户启用的技能集（`hallmark`, `frontend-design`, `shadcn`, `improve-codebase-architecture`, `grill-me`, `grill-with-docs`），做出以下架构与设计决策：

1. **工作台架构演进**：
   - 弃用顶部容易跳动的多功能混合 Tab，采用 **左侧深色微质感导航栏 (Sidebar) + 顶部稳定动作坞 (Header) + 沉浸式工作区 (Workspace)** 布局。
2. **构建深度模块 `ReplenishHubView`**：
   - 将「补货汇总」与「更新良品库存」合并为两步流转工作台。
   - 建立 **内存直通管道 (Memory Pipeline)**：第一步计算生成的表三数据可直接一键流转给第二步库存校准，同时保留从外部导入历史表三的独立通道。
3. **建立统一主数据中心 `MasterDataDialog`**：
   - 集中聚合：商品档案库、仓库与工厂预设、仓库映射字典、品牌商品排序、猫超开票资质，一站式维护。
4. **严格执行 Design & Code 约束**：
   - 遵循 `docs/CONSTRAINTS.md`，执行反 AI-Slop 原则、锁定语义 Token、禁止斜体标题、使用 `size-*`、消除 `space-x-*` / `space-y-*`，保证 8 态交互完备性。
   - 保持底层 61 个单元测试 100% 通过，不侵入核心计算逻辑。

## 结果与收益 (Consequences)
- **正面收益**：
  - 补货到库存校准的流转操作减少 50% 以上点击与文件选择步骤。
  - 主数据维护入口统一清晰，彻底消除了寻找配置的认知成本。
  - 符合专业 B 端设计规范与严谨的 shadcn/Tailwind 代码标准。
- **合规保证**：
  - 底层 Excel 核心算法、公式写入、送货单拆分与开票规则与原有系统完全兼容。
