# 仓配订单汇总工具

Electron 桌面端 Excel 汇总工具，支持两种工作模式：

- 库存模式：仅导入表二，按品牌生成直营仓库存汇总。
- 完整订单模式：同时导入表一和表二，汇总采购数量并自动计算建议补货。
- 送货单生成：导入商品资料和 ReceiptNote，按品牌、仓库生成送货单。

## 使用

```powershell
npm install
npm start
```

生成 Windows 安装包：

```powershell
npm run dist
```

## 汇总规则

- 表一使用“仓库名称、货品名称、品牌名称、采购数量、箱规”。
- 表一中相同“仓库名称 + 货品名称”的订单合并为一行，采购数量累加。
- 表二按品牌筛选，只保留 RDC 和 MRDC 仓角色。
- 完整模式以表一为准，取所选品牌的全部商品作为统一清单；每个已映射仓库都输出相同商品种类，原本没有订单的组合系统订单为 0。
- 良品可用取表二的“在库良品库存件数”。
- 系统订单重量（吨）= 系统订单 × 单件规格（kg）÷ 1000。
- 预计未来30天销量 = 近30天出库 × 50% + 近7天日均 × 30 × 30% + 近1天出库 × 30 × 20%。
- 目标库存 = 预计未来30天销量 × 80%。
- 补货缺口 = max（0，目标库存 - 良品可用）。
- 有表一时，建议实际订单按箱规向上取整，但不得超过系统订单；仅有表二时，直接按库存与销量计算补货需求，不受系统订单为 0 限制。
- 仓库汇总行的“实际订单安排”直接使用明细合计，不进行额外取整。
- “安排状态”列保留为空，不自动填写状态或补货提示。
- 导出的 Excel 保留重量、实际订单安排、实际重量计算公式，以及各仓库汇总行的 `SUM` 公式；修改源数据后可由 Excel 自动重算；公式兼容常见 Excel 与 WPS 版本。
- 界面和导出文件仅固定表头，不固定左侧仓库名称、货品名称列。

模板中的常用商品已内置规格；其他商品优先从货品名称解析 kg 规格，无法识别时规格为 0，需要复核。
## 前置仓到直营仓映射

该功能用于处理表一的仓库名称与表二的直营仓名称不一致的情况。

### 匹配顺序

1. 精确匹配：如果表一的“仓库名称”与表二的“物理仓名称”完全一致，系统直接建立对应关系。
2. 城市匹配：名称不一致时，系统尝试根据名称中的城市自动匹配。例如“菜鸟成都双流前置仓”可匹配到“华西成都直营商超仓”。
3. 手动选择：无法自动匹配时，可以在“仓库映射”窗口中为表一仓库选择对应的表二直营仓。

### 数据安全规则

- 手动确认的映射关系保存在本机，下次遇到相同仓库时自动使用。
- 未成功映射的系统订单不会被分配到其他仓库，也不会计入表三。
- 界面会显示未映射仓库数量和涉及的系统订单数量，避免订单被错误归仓。

### 当前模板说明

当前 `template1.xlsx` 中的“仓库名称”已经是直营仓名称，并且能够与 `template2.xlsx` 的“物理仓名称”精确对应，因此通常不需要手动设置仓库映射。

该功能主要用于兼容以后出现前置仓名称、仓库简称或不同系统仓库名称的文件。


## 送货单生成功能

1. 导入 `product.xlsx` 和 `ReceiptNote.xlsx`，系统按条形码关联商品资料。
2. 商品品牌以商品资料表为准；品牌和仓库都可以多选，只生成勾选范围内的送货单；同一文件不会混入其他品牌。
3. 默认每个品牌生成一个 Excel，并按仓库建立完整名称的工作表；也可勾选“按仓库拆分为多个 Excel”，使每个仓库单独生成文件。
4. 送货单数据以 ReceiptNote 为准：
   - 箱规取“采购规格(箱规数)”；
   - 包数取“商品实际发货数量”；
   - 箱数 = 包数 ÷ 箱规；
   - 箱数出现小数时，对应单元格自动标红。
5. 同一仓库内相同的“物流宝单号”（ReceiptNote 的 `LBX号`）会在送货单 B 列纵向合并。
6. 生产日期选填；生成前可搜索商品名称并单选或多选，批量设置或清除生产日期，不填写生产批号。
7. 保质期、联系方式在生成前统一填写；默认分别为 360 天和 17771571056，可修改。
8. 供应商名称为全局配置，默认“湖北国宝桥米有限公司”，修改后保存在本机。
9. 供应商编码取 ReceiptNote，送货日期优先取“预约入库时间”，缺失时取“期望到货时间”。
10. 导出的送货单沿用模板的横向打印和单页宽度设置。

## 分品牌商品清单

- 每个品牌分别维护自己的商品名称和导出顺序。
- 首次使用时，默认从当前品牌的表一订单中提取货品名称，按首次出现顺序去重；没有表一时从表二按相同规则生成。
- 在“商品清单”中一行填写一个商品，行顺序就是表三的导出顺序；保存后配置会保存在本机。
- 点击“恢复默认”只清除当前品牌的自定义配置，并重新读取当前导入文件生成默认清单。
- 每个仓库都按同一商品清单输出；没有订单的仓库商品组合，系统订单为 0；清单外商品不进入补货汇总。

## 实际订单回填

1. 在完整订单模式导出表三时，工具会在表三中保存隐藏的回填任务信息和订单原表快照；关闭工具后仍可继续处理。
2. 业务人员修改表三的“实际订单安排”后，点击“回填订单原表”重新导入该表三。
   - 新版表三带有隐藏回填任务，可直接识别原表。
   - 旧版表三没有隐藏任务时，工具会继续提示选择当时对应的订单原表。
3. 工具按“仓库名称 + 货品名称”匹配订单原表。同一仓库、同一货品存在多条采购明细时，按订单原表的行顺序依次分配，每行不超过“采购数量”。
4. 实际订单安排必须是大于等于 0 的整数。超过采购数量总和、找不到订单明细或存在重复组合时，对应仓库会标记为异常并跳过。
5. 校验通过后，每个仓库单独生成一个 `仓库名称-补货单.xlsx`，保留订单原表结构，只更新“供应商确认数量”，不会覆盖原文件。

## 更新表三良品库存

1. 切换到“更新良品库存”，先导入需要更新的旧表三。
2. “实时库存”和“库存在途明细”二选一即可，也可以同时导入；实时库存支持一次选择多个 Excel，适合每个仓库单独导出一份库存文件的场景。
3. 导入实时库存时，工具按“仓库名称 + 货品名称”精确匹配，只更新旧表三的“良品可用”；数值 0 会正常写入。
4. 实时库存没有覆盖到的表三明细保留原值，库存中不属于当前表三的货品会忽略。
5. 同一库存文件内的重复组合会合计；不同库存文件若出现相同仓库和货品会提示冲突并阻止导出，避免重复计算。
6. 导入“库存在途明细”后，按“仓库名称 + 货品名称”汇总“剩余数量”，在表三末列生成“在途订单”。只覆盖在途文件中出现的仓库：这些仓库内未匹配商品写 0；文件中没有出现的仓库保留原有结果。仓库汇总行保留 `SUM` 公式。
7. 导出会生成一份新表三，保留旧表三的其他字段、公式、样式和隐藏回填任务信息，不覆盖原文件。
