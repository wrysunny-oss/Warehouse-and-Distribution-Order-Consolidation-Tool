# 仓配订单汇总工具

Electron 桌面端 Excel 汇总工具，支持两种工作模式：

- 库存模式：仅导入表二，按品牌生成直营仓库存汇总。
- 完整订单模式：同时导入表一和表二，汇总采购数量并自动计算建议补货。

## 使用

```powershell
npm install
npm start
```

生成 Windows 安装包：

```powershell
npm run dist
```

## 汇总规则

- 表一使用“仓库名称、货品名称、品牌名称、采购数量、箱规”。
- 表三按表一订单行逐行生成；即使仓库名称和货品名称相同，也分别保留，采购数量不合并相加。
- 表二按品牌筛选，只保留 RDC 和 MRDC 仓角色。
- 完整模式按表一逐行输出；仓库名称和货品名称以表一为准，不对重复组合去重。
- 良品可用取表二的“在库良品库存件数”。
- 系统订单重量（吨）= 系统订单 × 单件规格（kg）÷ 1000。
- 预计未来30天销量 = 近30天出库 × 50% + 近7天日均 × 30 × 30% + 近1天出库 × 30 × 20%。
- 目标库存 = 预计未来30天销量 × 80%。
- 补货缺口 = max（0，目标库存 - 良品可用）。
- 建议实际订单按箱规向上取整，但不得超过系统订单。
- 仓库汇总行的“实际订单安排”直接使用明细合计，不进行额外取整。
- “安排状态”列保留为空，不自动填写状态或补货提示。
- 导出的 Excel 保留重量、实际订单安排、实际重量计算公式，以及各仓库汇总行的 `SUM` 公式；修改源数据后可由 Excel 自动重算；公式兼容常见 Excel 与 WPS 版本。
- 界面和导出文件仅固定表头，不固定左侧仓库名称、货品名称列。

模板中的常用商品已内置规格；其他商品优先从货品名称解析 kg 规格，无法识别时规格为 0，需要复核。
## 前置仓到直营仓映射

该功能用于处理表一的仓库名称与表二的直营仓名称不一致的情况。

### 匹配顺序

1. 精确匹配：如果表一的“仓库名称”与表二的“物理仓名称”完全一致，系统直接建立对应关系。
2. 城市匹配：名称不一致时，系统尝试根据名称中的城市自动匹配。例如“菜鸟成都双流前置仓”可匹配到“华西成都直营商超仓”。
3. 手动选择：无法自动匹配时，可以在“仓库映射”窗口中为表一仓库选择对应的表二直营仓。

### 数据安全规则

- 手动确认的映射关系保存在本机，下次遇到相同仓库时自动使用。
- 未成功映射的系统订单不会被分配到其他仓库，也不会计入表三。
- 界面会显示未映射仓库数量和涉及的系统订单数量，避免订单被错误归仓。

### 当前模板说明

当前 `template1.xlsx` 中的“仓库名称”已经是直营仓名称，并且能够与 `template2.xlsx` 的“物理仓名称”精确对应，因此通常不需要手动设置仓库映射。

该功能主要用于兼容以后出现前置仓名称、仓库简称或不同系统仓库名称的文件。
